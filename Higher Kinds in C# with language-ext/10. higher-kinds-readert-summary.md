## 核心概念

### 1. 背景与动机

这是一个多部分系列文章，本篇专注于 ReaderT monad transformer。在之前的文章中：
- 介绍了 monad transformers 的基础概念
- 主要讨论了 `MaybeT` transformer（将 `OptionT` 提升到 IO monad 中创建可选的副作用）
- 展示了如何通过包装 monad-transformer 堆栈创建"领域 monads"

### 2. Language-ext v5 的重要性

在引入高阶类型方法之前，language-ext 存在的问题：
- 无法编写适用于**所有** monads 或**所有** functors 的通用代码
- 必须为每个组合手动构建各种预组合的 monads（如 `OptionAsync`、`EitherAsync`、`TryOption` 等）
- 用户需要等待库作者构建这些组合

**现在的改进**：
- 这些抽象已经存在
- 可以使用 `ValidationT<F, IO, A>` 等 monad transformer 堆栈
- 不再需要等待预构建的组合 monads

### 3. ReaderT<Env, M, A> 详解

#### 基本定义
```csharp
public record ReaderT<Env, M, A>(Func<Env, K<M, A>> runReader) : K<ReaderT<Env, M>, A>
    where M : Monad<M>
{
    public K<M, A> Run(Env env) =>
        this.runReader(env);
    
    // ...
}
```

#### 核心特性

**ReaderT 的作用**：
- 为给定的 monad `M` 添加一个**静态环境** `Env`
- 可以将其与 `IO` monad 组合以获得静态环境和副作用

**关键机制**：
- `ReaderT` 会自动将 `MyConfig` 值线程化到计算中
- 使用声明式方式处理环境传递
- 通过 `ReaderT.ask<IO, MyConfig>()` 访问配置

#### 示例用法

**简单示例**：
```csharp
public static ReaderT<MyConfig, IO, string> readSourceText(string file) =>
    from config in ReaderT.ask<IO, MyConfig>()
    let path = Path.Combine(config.SourceFolder, file)
    from text in IO.liftAsync(e => File.ReadAllTextAsync(path, e.Token))
    select text;
```

**运行 ReaderT**：
```csharp
// 创建配置对象
var configObj = new MyConfig("c:\\folder");

// 运行 ReaderT，返回 IO<string>
var configTextIO = readSourceText("test.cs").Run(configObj);

// 运行 IO
var configText = configTextIO.Run();
```

#### 与 MaybeT/OptionT 的区别

- **MaybeT/OptionT**: `K<M, A>` 是 **inner** 类型，`OptionT` 是 **outer** 类型
- **ReaderT**: `K<M, A>` 是 **outer** 类型

这种差异是为了适应特定 transformer 的最佳实现：
- 对于可选类型，结果应该是可选的（outer 类型包装）
- 对于有状态计算类型，lifted monad 包装有状态计算

### 4. Readable Trait

#### Readable 的定义

`Readable` 是一个专门为 readers 设计的 trait：

```csharp
public interface Readable<M, Env>
    where M : Readable<M, Env>
{
    public static abstract K<M, A> Asks<A>(Func<Env, A> f);
    
    public static virtual K<M, Env> Ask =>
        M.Asks(Prelude.identity);
    
    public static abstract K<M, A> Local<A>(
        Func<Env, Env> f,
        K<M, A> ma);
}
```

#### 核心功能

**Readable 的作用**：
- 抽象了访问静态环境的概念
- 使代码可以接受任何"可读"类型（`Eff`、`ReaderT`、`Reader` 或任何自定义类型）

**实现示例**：
`Eff<RT>` 实现了 `Readable` 接口：

```csharp
public class Eff<RT> : Monad<Eff<RT>>, Readable<Eff<RT>, RT>
{
    // ... 来自之前的实现 ...
    
    public static K<Eff<RT>, A> Asks<A>(Func<RT, A> f) =>
        new Eff<RT, A>(ReaderT.RT, IO, A>.Asks(f));
    
    public static K<Eff<RT>, A> Local<A>(Func<RT, RT> f, K<Eff<RT>, A> ma) =>
        new Eff<RT, A>(ma.As().runEff.Local(f));
}
```

#### 实际应用

**泛化函数示例**：
```csharp
public static K<M, int> addRdr(K<M, int> mx, K<M, int> my)
    where M : Readable<M, int>, Monad<M> =>
    from x in mx
    from y in my
    from z in Readable.ask<M, int>()
    select x + y + z;
```

**使用示例**：
```csharp
var compute = addRdr(Eff.Pure<int, int>(100), Eff.Pure<int, int>(200));
var result = compute.Run(300).Run();  // 600
```

**关键特性**：
- `addRdr` 不知道运行的是什么 monad
- 不关心如何管理静态环境
- 完全从内部抽象出来
- 值是可绑定和可读的

### 5. 通用化示例

#### User Session 示例

```csharp
public record User(string Id);
public record Session(User LoggedIn, DateTime LastAccess);

public static K<M, Session> getSession<M>()
    where M : Readable<M, Session> =>
    ReaderM.ask<M, Session>();

public static K<M, User> getLoggedInUser<M>()
    where M : Readable<M, Session> =>
    ReaderM.asks<M, Session, User>(s => s.LoggedIn);
```

#### 优势

使用 `Monad` 约束和 `Readable` 约束：
- 可以编写适用于 `Db` monad、`Service` monad、`Api` monad 等的通用支持函数
- 可以嵌入安全角色和权限进行内联访问控制
- 可以扩展能力通过堆叠更多 transformers（如必要）

### 6. 真正的抽象

#### 核心思想

这是**真正抽象**的路径：
- 一切都是纯粹的
- 可以安全地抽象，因为所有组件都遵循规则
- 不存在"唯一正确的方式"来构建应用程序
- 使用纯函数式编程技术创建结构时：
  - 领域、层、组件和整体结构从组合类型（如 monads 和 monad-transformers）中自然演化
  - 可以从 10,000 英尺的高度突然"看到"架构结构

#### 对比 OOP

作者的体会：
- 在之前的 OOP 生涯中总是缺少这些清晰的时刻
- 纯函数式方法让架构变得流动且可塑（可以随需求改变）
- 架构本身变得**可组合**

## 总结

1. **ReaderT Monad Transformer**：
   - 为任何 monad 添加静态环境支持
   - 自动线程化环境值
   - 提供声明式的环境访问

2. **Readable Trait**：
   - 抽象化环境访问
   - 相当于 Haskell 的 MonadReader（不继承 Monad 约束）
   - 使代码更加通用和可重用

3. **实践价值**：
   - 创建纯粹的代码库
   - 构建可组合的架构
   - 将正确的架构融入手中
   - 适应需求变化时保持灵活性

4. **Language-ext v5 的影响**：
   - 开发者现在可以构建自己的函数式堆栈
   - 不再需要等待预构建的组合类型
   - 通过 monad transformers 实现强大的组合能力
